# PatioFinder — working notes for Claude Code

iPhone app: a Find-My-style arrow that rotates (via the device compass) to point
at the nearest outdoor restaurant **patio**, showing live distance. Swipe the
arrow to cycle patios; list button jumps to any; map button shows it on a map.
SwiftUI + CoreLocation + MapKit, **iOS 17+**, no third-party dependencies.

## How to build / deploy
- **One command:** `./deploy.sh` — regenerates the project (XcodeGen), builds,
  signs, installs, and launches on the connected iPhone. Overrides:
  `--team`, `--bundle-id`, `--device`, `--config`.
- Runtime needs a **physical iPhone** for the compass; the **Simulator has no
  magnetometer**, so the arrow won't rotate there (everything else works —
  location can be simulated, list/map/swipe all function).
- Project file is **generated by XcodeGen** from `project.yml` (source of truth).
  `PatioFinder.xcodeproj` is gitignored. Run `xcodegen generate` to open in Xcode.

## Data sources (see `PatioFinder/Services/`)
Load order in `PatioViewModel.load`: **Google Places (New) → Apple MapKit → seed**.
1. `GooglePlacesProvider` — `places:searchNearby` (restaurants, bars, cafés, bakeries),
   keeps `outdoorSeating == true`. Popularity-ranked in a compact radius, widening to a
   distance pass over ~15 mi when thin (self-adapts city vs rural). Sends
   `X-Ios-Bundle-Identifier` so the bundle-id-restricted key isn't 403'd.
2. `MapKitPatioProvider` — keyless `MKLocalSearch`; local results with no API key.
3. `SeedPatioProvider` — bundled `Resources/Patios.json` (SF samples), offline last resort.

**API key:** lives in `Config.xcconfig` as `GOOGLE_PLACES_API_KEY` (gitignored —
never commit it). `Config.example.xcconfig` is the template; `deploy.sh` copies it
if `Config.xcconfig` is missing. The key surfaces via `Info.plist` → `AppConfig`.
